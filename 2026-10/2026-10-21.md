## Reactでタスク一覧ページを作成（TypeScript / Hooks / Props）

タスク一覧ページの作成を通して、TypeScriptによる型定義、React Hooksを使用した状態管理、Container/Presentationalパターンによるコンポーネントの分割を学んだ。

### ① TypeScriptによる型定義

`src/types/task.ts`

```
export type Priority = "high" | "medium" | "low";

export interface Task {
  id: number;
  title: string;
  status: boolean;
  priority: Priority;
  dueDate: string;
}
```

- `interface`は、オブジェクトが持つプロパティとその型を定義する。
- `Priority`はリテラル型を使い、指定した3種類の文字列だけを許可する。
- 型を定義することで、想定外のデータを開発時に検出しやすくなる。

※ Railsのデータベース設計に少し似ているが、TypeScriptの型定義はDBの構造を作るものではなく、プログラム内で扱うデータの形を決めるもの。

### ② モックデータと非同期処理

モックデータとは、APIなどから取得するデータの代わりに使用する仮のデータ。

```
export const getTasks = (): Promise<Task[]> => {
  return new Promise((resolve) => {
    setTimeout(() => resolve([...mockTasks]));
  });
};
```

- `()`：関数が受け取る引数。今回は引数なし。
- `Promise<Task[]>`：将来的にTask型の配列を取得できることを表す戻り値の型。
- `new Promise()`：非同期処理の結果を管理する。
- `resolve()`：Promiseを成功状態にし、結果を渡す。
- `[...mockTasks]`：スプレッド構文で配列をコピーする。

※ `[...]`で新しい配列を作成しているが、配列内のオブジェクト自体はコピーされず、参照が共有される。

### ③ useStateとuseEffectによる状態管理

```
const [tasks, setTasks] = useState<Task[]>([]);

useEffect(() => {
  const fetchTasks = async () => {
    const fetchedTasks = await getTasks();
    setTasks(fetchedTasks);
  };
  fetchTasks();
}, []);
```

- **useState**：コンポーネントが保持するデータ（state）を管理する。
- `useState<Task[]>([])`：Task型の配列を空の状態で初期化する。
- **useEffect**：画面表示後のデータ取得など、副作用の処理を実行する。
- `async / await`：Promiseの結果を待ってから次の処理を実行する。
- `setTasks(fetchedTasks)`：取得したデータでstateを更新し、再レンダリングにつなげる。

`useEffect`の依存配列による違い

- 省略：基本的に毎回のレンダリング後に実行。
- `[]`：初回表示後に実行。
- `[id]`：初回表示後と、`id`が変化した後に実行。

※ 開発環境のStrict Modeでは、`useEffect`が初回に追加実行されることがある。

### ④ Container / Presentationalパターン

データの取得・管理と画面への表示を、別々のコンポーネントに分ける設計手法。

- **TaskListContainer（Container）**：タスクデータの取得と状態管理を担当する。
- **TaskCard（Presentational）**：受け取ったタスクデータを表示する。

```
{tasks.map((task) => (
  <TaskCard key={task.id} task={task} />
))}
```

- `map()`でタスクの配列を一件ずつ処理する。
- `TaskCard`に`task={task}`でデータをpropsとして渡す。
- `key={task.id}`はReactが各要素を識別するために使用する。

受け取る側ではpropsの型を定義する。

```
type Props = {
  task: Task;
};

export default function TaskCard({ task }: Props) {
  return <h3>{task.title}</h3>;
}
```

- `Props`で受け取るデータの型を定義する。
- `{ task }`は分割代入で、propsからtaskを取り出している。
- 処理と表示を分けることで、コードの役割が明確になり、保守しやすくなる。

### まとめ

今回のタスク一覧表示の流れは、

**getTasksでデータ取得 → useStateで保持 → mapで展開 → propsでTaskCardに渡す → 画面表示**

という仕組み。

TypeScriptでデータの形を定義し、React Hooksで状態を管理する。また、Container/Presentationalパターンによって、データの管理と表示の役割を分離できることを学んだ。
