## メモ
1. あらためてincludeについて

`include` は、moduleにまとめたメソッドを、Controllerなどのクラス内で使えるようにする仕組みで、たとえば、ログイン確認や現在のユーザー取得など、複数のControllerで使う処理を毎回書くと重複してしまう。  
そのため、共通処理をmoduleにまとめて、Controller側で `include` して使う。
例として
    module SessionsHelper
      def current_user
        @current_user ||= User.find_by(id: session[:user_id])
      end
      def logged_in?
        current_user.present?
      end
    end
Controller側でincludeする。

    class ApplicationController < ActionController::Base
      include SessionsHelper
    end
これで、`ApplicationController` や、それを継承したControllerで `current_user` や `logged_in?` を使えるようになる。
なお、includeしただけでは実行されない
`include` は、メソッドを使えるようにするだけで、自動で実行するものではない。
たとえば、`require_login` を使いたい場合は、別途呼び出す必要がある。
    before_action :require_login
つまり役割はこう。
include → メソッドを使えるようにする
 before_action→ そのメソッドをActionの前に実行する
また、renderとの違い`render` は画面の部品を表示するもの。
`include` はRubyのメソッドを使えるようにするもので、画面を読み込むのが `render`、処理を使えるようにするのが `include`。

`include` は、共通処理をmoduleにまとめてControllerで使えるようにするための仕組みだと理解した。
Controllerでは、ログイン確認・現在のユーザー取得・管理者チェックなど、複数のControllerで使う処理に利用される。
ただし、`include` しただけでは処理は動かない。  実際に動かすには、`before_action` やAction内でメソッドを呼び出す必要がある。 → そのメソッドをActionの前に実行する
