### `||`**&#x20;と&#x20;**`or`**&#x20;の違い**

```
v1 = 1 - 1 == 0  # => true
v2 = v1 || raise RuntimeError
puts v2 && false
```

**SyntaxError（構文エラー）**

- `||` は `or` より優先順位が高い。
- `v1 || raise RuntimeError` は構文解析でエラーになる。
- `v1` が `true` でも、短絡評価より先に構文解析されるためエラーになる。

### **正しい書き方**

```
v2 = v1 or raise RuntimeError
v2 = v1 || raise(RuntimeError)
v2 = v1 || (raise RuntimeError)
```

いずれも正常に実行でき、最終的に `false` が表示される。

### **ポイント**

- `||` → `or` より優先順位が高い
- `&&` → `and` より優先順位が高い
- `||` → 左辺が真なら右辺を評価しない
- `&&` → 左辺が偽なら右辺を評価しない
- **短絡評価では構文エラーを回避できない**
